# magomap PWA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The installable, offline-first magomap app. It has a map of saved and previous locations, Kakao search, a place page with the visit diary and links, lists, the Kakao import, and the account page. It is in Korean and English, with phone and desktop layouts. A Korean/English GitHub Pages homepage links to it.

**Architecture:**
- `apps/web` is a Vite + React SPA, served as static assets by the plan 01 Worker, from the same origin.
- The UI reads **only** from IndexedDB (Dexie). Every local write goes into the same Dexie transaction as an outbox entry. A sync engine pushes and pulls against `/api/sync/*`.
- The map sits behind a `MapAdapter` interface, with a Kakao SDK implementation and a Leaflet fallback.
- `apps/homepage` is a separate static site.

**Tech Stack:** React 19, Vite, TypeScript, `vite-plugin-pwa` (generateSW), Dexie + `dexie-react-hooks`, `wouter`, `i18next` + `react-i18next`, Leaflet + `leaflet.markercluster`, the Kakao Maps JS SDK, Vitest + Testing Library + `fake-indexeddb`, Playwright.

**Spec:** `/home/motoko/workspace/magomap/docs/superpowers/specs/2026-11-19-magomap-design.md`, including its addenda: location history, phone and desktop layouts, and the homepage.

**Order:** this is plan 02 of 3. Build it after plan 01.

**Build process:** every task follows `docs/superpowers/build-process.md`. The UI reviewer needs screenshots, so on screen tasks the builder saves Playwright screenshots of the changed screens to `tmp/review-shots/02-<task>/`, at 390×844 and 1440×900, in light and dark.

**Depends on:** plan 01. This plan uses `@magomap/domain` (types, ids, schemas), its routes, and its dev scripts `apps/api/scripts/fake-kakao-list.ts` and `dev:seed`.

## Global Constraints

**Language**
- Every user-visible string goes through i18next, in `src/i18n/ko.json` and `src/i18n/en.json`. The two files have identical key sets.
- The language is `localStorage["mm.lang"]` if set. Otherwise it is `ko` when `navigator.language` starts with `ko`, and `en` otherwise.
- Dates use `Intl.DateTimeFormat(lang, { dateStyle: "long" })`.
- Kakao data is shown as-is.

**Local storage**
- The IndexedDB database is named `magomap-<userId>`, so each account has its own data and outbox.
- **Only "Delete account" removes it.** Signing out keeps it.
- After sign-in, call `navigator.storage.persist()` once.

**Writes**
- Every local write sets `clientUpdatedAt = max(Date.now(), existing.updatedAt + 1)`, so device clock skew can't make a fresh edit look stale.
- Membership ids come from `ownMembershipRowId`. Place ids come from `kakaoPlaceRowId`.

**Limits** (the same as the server)
- Visit-note body ≤ 20,000 characters.
- Link URL `http(s)` only, ≤ 2,048 characters.
- List name ≤ 100 characters.
- A push batch is at most 200 mutations **and** at most 900 KB of JSON.

**Kakao data**
- Kakao lists, their memberships and their Kakao notes are read-only.

**Map**
- Kakao SDK when `PublicConfig.kakaoJavascriptKey` is set and the script loads within 8 s; Leaflet + OSM otherwise. A caption shows which map is in use.
- Colours come from `KAKAO_PLACE_COLORS[code].value`, copied from `kakao-list/apps/pwa/src/App.tsx:39` into `src/map/kakaoColors.ts`.

**Layout and look**
- **Two layouts with one breakpoint at 768 px.**
  - Phone: full-screen map, sheets, and full-screen pages with back.
  - Desktop: a persistent left panel (360–420 px) beside the map.
- Playwright checks both viewports: `phone` at 390×844 with touch, and `desktop` at 1440×900.
- Touch targets are at least 44 px. Light and calm, familiar to Kakao Map users, with dark mode via `prefers-color-scheme`.
- Use the `frontend-design` skill when building screens.
- **Brand:** `docs/brand-guidelines.md` is the source of truth for colours (light and dark), the own-list colour presets, marker styles, type, radius, elevation and voice in Korean and English.
  - `apps/web/src/styles/tokens.css` defines every colour in it as CSS variables, starting from `assets/design-tokens.css` (the generated primary/secondary scales).
  - `apps/homepage` imports the same `tokens.css`.
  - Kakao yellow is never used.
- The 8 own-list colour presets (Task 6) are the ones listed in the guidelines' "Map Markers" section.

**Local dev**
- Run `wrangler dev --env d1` (there is no `--local` flag) with `ALLOW_DEV_LOGIN=true`.
- Run the fake kakao-list on `:8788`, with `KAKAO_LIST_URL=http://localhost:8788`.

## Review Focus

- **A note written offline, then the app killed before reconnecting**, including iOS discarding the backgrounded PWA mid-typing. Expect the saved note to survive and sync, and the unsaved draft to survive too. Tested in Task 2 (unit), Task 5 (drafts) and Task 7 (Playwright).
- **The server rejects a whole push** (400/413/5xx). Expect 5xx to back off and retry, and 400/413 to split the batch until the bad entry is isolated in `rejected`, with everything else syncing. Tested in Task 2.
- **The device clock is behind.** Expect an edit to still win over the version it was based on; a genuine `ignored_stale` brings the server row back. Tested in Task 2.
- **Signing out with unsynced changes.** Expect a warning with the count, and the data kept for the next sign-in as the same user. Tested in Task 1.
- **The Kakao SDK fails to load.** Expect a working Leaflet map captioned "OpenStreetMap". Tested in Task 3.

### Task 2: Local store, outbox and sync engine

**Files:**
- Create in `apps/web/src/data/`:
  - `db.ts`, `writes.ts`, `sync.ts`, `queries.ts`, `useSyncStatus.ts`;
  - `sync.test.ts`, `writes.test.ts`.

**Interfaces:**
- **Dexie tables:**
  - `places`, `lists`, `list_items` (indexed on `listId` and `placeId`), `visit_notes` (`placeId`), `links` (`placeId`), `place_locations` (`placeId`);
  - `outbox` (`++seq`, `mutationId`, `table`, `id`, `op`, `row`, `clientUpdatedAt`);
  - `rejected` (`mutationId`, `table`, `id`, `row`, `reason`, `at`);
  - `drafts` (`key`: `new:<placeId>` | `edit:<noteId>`, `visitedOn`, `body`, `updatedAt`);
  - `meta` (`cursor`, `lastSyncAt`).
- `openUserDb(userId: string): MagomapDexie`
- **Writes** (`writes.ts`). Each runs in one Dexie transaction that writes the row and appends the outbox entry.
  - Diary: `addVisitNote(placeId, { visitedOn, body })`, `editVisitNote(id, patch)`, `deleteVisitNote(id)`.
  - Links: `addLink(placeId, { url, title })`, `editLink(id, patch)`, `deleteLink(id)`.
  - `savePlaceFromSearch(result: SearchResult): Promise<string>`:
    - when it isn't saved yet, it creates the place `kp_<id>` with `source: "search"`;
    - when it is saved but soft-deleted, it upserts it to restore it;
    - when it is already saved and live, it returns the id with no write.
  - `refreshPlaceFromSearch(result: SearchResult): Promise<void>`: when any of lat, lng, address or roadAddress differs from the saved place, it upserts the place with the new location fields. The server decides whether that counts as a move.
  - `deletePlace(id)`: writes the place tombstone only. Notes and links are kept, so restoring brings them back.
  - Lists: `createList({ name, color })`, `editList(id, patch)`, `deleteList(id)`.
  - Membership:
    - `addToList(listId, placeId)`: id `ownMembershipRowId(listId, placeId)`; re-adding a tombstoned one restores it; `position` is the list's max position + 1;
    - `removeFromList(listItemId)`.
  - Drafts: `saveDraft(key, value)` (debounced 500 ms by the caller), `clearDraft(key)`, `useDraft(key)`.
- **Sync** (`sync.ts`):
  - `syncNow(): Promise<SyncResult>`, where `SyncResult = { pushed: number; pulled: number; rejected: number }`.
  - `startSyncTriggers(): () => void` syncs on start, on `online`, on becoming visible, 2 s after a write, after an import, and every 60 s while in the `error` state with backoff.
  - Only one sync runs at a time; a second call joins the first.
- **Sync rules:**
  1. Push the outbox in batches limited by count and bytes (Global Constraints).
     - `applied`: remove the entry.
     - `ignored_stale`: remove it and **write the returned server row locally**.
     - `rejected`: move it to `rejected` with its row.
  2. A 401 stops sync, keeps the outbox, and sets `needs_signin`.
  3. A network error stops sync and sets `offline`.
  4. A 5xx or 429 stops sync, sets `error`, and backs off: 5 s, 30 s, 2 min, then 10 min.
  5. A 400 or 413 **splits the batch in half and retries** each half, recursively. A single mutation that still gets 400 or 413 is moved to `rejected` with reason `invalid`.
  6. Pull pages until `hasMore` is false. **Each page's rows and its cursor are written in one Dexie transaction.**
  7. A pulled row is not applied while the outbox still has an entry for the same `table`/`id`.
- `useSyncStatus(): { state: "idle" | "syncing" | "offline" | "needs_signin" | "error"; unsynced: number; rejected: number; lastSyncAt?: number }`
- **Queries** (`queries.ts`). They all hide soft-deleted rows, and memberships whose place is deleted.
  - `usePlace(id)`, `usePlaceLinks(id)`.
  - `usePlaceNotes(id)`: ordered by `visitedOn` descending, nulls last, then `createdAt` descending.
  - `usePlaceMemberships(id)`, `useLists()`, `useListPlaces(listId)`.
  - `useVisiblePlaces(selectedListIds)`.
  - `usePlaceLocations(id)`: newest first.
  - `locationAt(placeId, at: number): PlaceLocationRow | null`: returns the history row with `validFrom ≤ at < validUntil`, or `null` when `at` falls in the current location. A `visitedOn` date is converted with `at = new Date(visitedOn + "T12:00:00").getTime()` (local noon).
  - `searchLocal(q)`: case-insensitive over titles, addresses, note bodies and link titles.
  - `useRejected()`: the items in `rejected`, with their text, for the indicator sheet.

- [ ] **Step 1: Write the failing tests** (`fake-indexeddb`, with `apiFetch` mocked):
  - **Offline write survives a restart:** a note added offline is still there after reopening the database, and `outbox.count() === 1`.
  - **Push results:**
    - `applied` empties the outbox;
    - `ignored_stale` with a server row empties it **and** replaces the local row;
    - `rejected` moves the entry to `rejected` and keeps the body.
  - **Whole-push failures:**

  - **Location history:**

### Task 6: Lists and import screens

**Files:**
- Create in `apps/web/src/screens/`: `ListsScreen.tsx`, `ListScreen.tsx`, `ImportScreen.tsx`.
- Create `apps/web/src/import/runImport.ts` and `apps/web/src/import/runImport.test.ts`.

**Interfaces:**
- `runImport(onProgress: (p: { listIndex: number; listCount: number }) => void): Promise<ImportSummary>` runs these steps:
  1. `GET /api/import/kakao/source`, parsed with `importContractSchema`;
  2. `POST /api/import/runs` with `{ complete, importedAt }`;
  3. for each list: `PUT …/lists/:kakaoFolderId/chunks/:i` in chunks of 500 items, then `POST …/lists/:kakaoFolderId/finish`;
