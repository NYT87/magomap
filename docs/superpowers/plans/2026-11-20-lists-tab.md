# One Lists tab, and import from kakao-list in Account — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Lists tab becomes the one place to choose which lists show on the map (a switch per row, tap the row to open it, empty sections hidden). Import moves from its own tab into the Account screen and says "kakao-list".

**Architecture:**
- `map/ListPicker.tsx` stays the component that owns visibility (`useMapPrefs`), but its rows become a link plus a separate switch.
- `screens/ListsScreen.tsx` renders it under the title and the New list button.
- The map's sheet and the desktop panel's picker are removed.
- `screens/ImportScreen.tsx` becomes an `ImportSection` rendered inside `screens/Account.tsx`. The Import tab is dropped, and `/import` redirects to `/account`.

**Tech Stack:** React 19, wouter, i18next (ko/en), Vitest + Testing Library, Playwright e2e (phone and desktop projects).

**Spec:** `docs/superpowers/specs/2026-11-20-lists-tab-design.md`

## Global Constraints

- **Strings:** every string exists in both `apps/web/src/i18n/ko.json` and `en.json`.
- **Gate:** `TEST_DATABASE_URL=postgres://magomap:magomap@localhost:5432/magomap_test ./scripts/gate.sh` must PASS.
  - No `@ts-ignore`, `biome-ignore`, `.skip`/`.only` or `as any`.
  - Never delete test files or weaken tests.
- **Protected paths:** `scripts/`, `biome.json`, `tsconfig.base.json`, `docs/superpowers/**` except this plan.
- **Layouts and themes:** screens work in both themes and both layouts (phone < 768 px, desktop).
- **Touch targets:** at least 44 px. The switch and the row link are separate targets, and the switch never navigates.
- **Kakao wording:** "Removed from Kakao", "Open in Kakao Map", the read-only note and "Subscribed in Kakao" stay as they are.
- **Visibility storage:** stays `mapPrefs` (per account, per device). No change to its storage format.
- **Commits:** end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Work happens on `main` (owner's choice).

## Review Focus

- **Tapping the switch must never open the list.** A tap near the switch should only toggle it. Pinned in Task 1.
- **Phone, from the map:** the lists button opens the Lists tab, and Back returns to the map with the choice applied. Pinned in Task 2's e2e.
- **Long list names:** names such as "cycling places for bap" or 500-place lists with an owner name must not push the switch off-screen at 360 px. Task 1 sets `min-width: 0` and ellipsis on the label; the Task 2 e2e asserts the switch is visible at phone width.
- **An account with no lists of its own:** no "My lists" heading at all. Pinned in Task 1.
- **Old `/import` links and bookmarks land on Account**, not on a blank page. Pinned in Task 3's e2e.

  - Each row is `<li class="mm-list-row">`, containing:
    - a wouter `<Link href="/lists/<encoded id>">` (swatch, name, count, "by owner" on subscribed rows, lock icon on read-only rows);
    - a `role="switch"` button with `aria-label={t("picker.toggle", { name })}`.
  - The saved row links to `/lists/__saved` (`SAVED_GROUP`).
  - Per-section Show all / Hide all stay.
  - A section renders only when it has rows; when no section has rows, `picker.hint` shows.
  - The Show previous locations switch stays at the bottom.
- New strings:
  - `picker.toggle`: en `"Show {{name}} on the map"`, ko `"지도에 {{name}} 표시"`.
  - `picker.hint`: en `"Your Kakao lists show up here after you import them from kakao-list in Account."`, ko `"카카오 리스트는 계정에서 kakao-list 가져오기를 하면 여기에 나타나요."`.
  - `picker.title` and `picker.none` are removed from both files. `picker.title` is still used by the map sheet, which Task 2 removes, so remove `picker.title` in Task 2.
