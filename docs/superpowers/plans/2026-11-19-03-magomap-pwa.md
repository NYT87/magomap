# magomap PWA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The installable, offline-first magomap app. It has a map of saved places, Kakao search, a place page with the visit diary and links, lists, the Kakao import, and the account page, in Korean and English.

**Architecture:**
- `apps/web` is a Vite + React SPA, served by the plan 02 Worker as static assets from the same origin.
- The UI reads **only** from IndexedDB (Dexie). Every local write goes into the same Dexie transaction as an outbox entry, and a sync engine pushes and pulls against `/api/sync/*`.
- The map sits behind a `MapAdapter` interface, with a Kakao SDK implementation and a Leaflet fallback.

**Tech Stack:** React 19, Vite, TypeScript, `vite-plugin-pwa` (generateSW), Dexie + `dexie-react-hooks`, `wouter`, `i18next` + `react-i18next`, Leaflet + `leaflet.markercluster`, the Kakao Maps JS SDK, Vitest + Testing Library + `fake-indexeddb`, Playwright.

**Spec:** `/home/motoko/workspace/magomap/docs/superpowers/specs/2026-11-19-magomap-design.md`

**Depends on:** plan 02. This plan uses its wire types from `@magomap/domain` and its routes.

## Global Constraints

- Every user-visible string goes through i18next, with keys in `src/i18n/ko.json` and `src/i18n/en.json`.
  - The language comes from `localStorage["mm.lang"]` if set; otherwise it's `ko` when `navigator.language` starts with `ko`, and `en` otherwise.
  - Dates use `Intl.DateTimeFormat(lang, { dateStyle: "long" })`.
  - Kakao data is shown as-is.
- The IndexedDB database is named `magomap-<userId>`. Each account gets its own database and outbox, so a different user signing in never pushes someone else's outbox.
- Visit-note bodies are ≤ 20,000 characters. Link URLs are `http(s)` only and ≤ 2,048 characters. List names are ≤ 100 characters. These match the server.
- Kakao lists and their memberships are read-only in the UI, and their Kakao notes are shown read-only.
- Map: Kakao SDK when `PublicConfig.kakaoJavascriptKey` is set and the script loads within 8 s; Leaflet + OSM otherwise. A small caption shows which map is in use.
- Copy the Kakao favourite colour map (`KAKAO_PLACE_COLORS`) from `kakao-list/apps/pwa/src/App.tsx:39` into `src/map/kakaoColors.ts`.
- Phone first. Touch targets are at least 44 px. Light and calm, familiar to Kakao Map users, with dark mode via `prefers-color-scheme`.

## Review Focus

- **A note written offline, then the app closed before reconnecting.** Expect it to still be there on reopen, marked unsynced, and pushed on the next connection. Tested in Task 2 (unit) and Task 7 (Playwright).
- **The session expires while there are unsynced changes.** Expect the outbox to be kept, a sign-in prompt shown, and the changes pushed after signing in again as the same user. Tested in Task 2.
- **A pull brings a server row for something with a pending local edit.** Expect the local edit to stay visible until its push resolves. Tested in Task 2.
- **The Kakao SDK fails to load (no key, blocked, over quota).** Expect a working Leaflet map and the caption "OpenStreetMap". Tested in Task 3.
- **The server rejects a mutation** (for example a link pointing at a place that no longer exists). Expect a visible "1 change couldn't be saved" with the text kept, not a silent drop. Tested in Task 2.

### Task 2: Local store, outbox and sync engine

**Files:**
- Create in `apps/web/src/data/`:
  - `db.ts`, `writes.ts`, `sync.ts`, `queries.ts`, `useSyncStatus.ts`;
  - `sync.test.ts`, `writes.test.ts`.

**Interfaces:**
- **Dexie tables:**
  - `places`, `lists`, `list_items`, `visit_notes`, `links`, keyed by `id`;
  - indexes: `list_items` on `listId` and `placeId`; `visit_notes` and `links` on `placeId`;
  - `outbox` (`++seq`, `mutationId`, `table`, `id`, `op`, `row`, `clientUpdatedAt`);
  - `rejected` (`mutationId`, `table`, `id`, `row`, `reason`, `at`);
  - `meta` (`key`: `cursor` | `lastSyncAt`).
- `openUserDb(userId: string): MagomapDexie`
- **Writes** (`writes.ts`). Each runs in one Dexie transaction: it writes the row with `updatedAt = clientUpdatedAt = Date.now()` and appends the outbox entry.
  - Diary: `addVisitNote(placeId, { visitedOn, body })`, `editVisitNote(id, patch)`, `deleteVisitNote(id)`.
  - Links: `addLink(placeId, { url, title })`, `editLink(id, patch)`, `deleteLink(id)`.
  - Places: `savePlaceFromSearch(result: SearchResult): Promise<string>`, which returns the place id `kp_<id>`, or the existing id if it is already saved. `deletePlace(id)`.
  - Lists: `createList({ name, color })`, `editList(id, patch)`, `deleteList(id)`.
  - Membership: `addToList(listId, placeId)`, `removeFromList(listItemId)`.
- **Sync** (`sync.ts`):
  - `syncNow(): Promise<SyncResult>`, where `SyncResult = { pushed: number; pulled: number; rejected: number }`.
  - `startSyncTriggers(): () => void` syncs on start, on the `online` event, when the page becomes visible, 2 s after any write (debounced), and after an import.
  - Only one sync runs at a time; a second call joins the first.
- **Sync rules:**
  1. Push the outbox in batches of 200. Remove entries the server marks `applied` or `ignored_stale`. Move `rejected` ones to the `rejected` table, keeping their row.
  2. Pull pages until `hasMore` is false, storing the cursor after each page.
  3. A pulled row is **not applied** while the outbox still has an entry for the same `table`/`id`. The local version stays.
  4. A 401 stops sync, keeps the outbox, and sets status `needs_signin`.
  5. A network error stops sync, keeps everything, and sets status `offline`.
- `useSyncStatus(): { state: "idle" | "syncing" | "offline" | "needs_signin"; unsynced: number; rejected: number; lastSyncAt?: number }`
- `queries.ts` holds the live-query hooks the screens use:
  - `usePlace(id)`, `usePlaceNotes(id)` (newest first: by `visitedOn` descending, nulls last, then `createdAt`), `usePlaceLinks(id)`;
  - `usePlaceMemberships(id)`, `useLists()`, `useListPlaces(listId)`;
  - `useVisiblePlaces(selectedListIds)`;
  - `searchLocal(q)`, which searches title, address, note bodies and link titles, case-insensitively.
  - All of them hide soft-deleted rows, and hide memberships whose place is deleted.

- [ ] **Step 1: Write the failing tests** (Vitest + `fake-indexeddb`, with `apiFetch` mocked):
  - **Offline write survives a restart:** `addVisitNote` while offline, then close and reopen the Dexie db. The note is still there and `outbox.count() === 1`.
  - **Push then pull:** `syncNow` after the push answers `applied` empties the outbox.
  - **`ignored_stale`** also empties the outbox.
  - **`rejected`** moves the entry to `rejected` and keeps the note body.
  - **Pending edit wins:** a pulled row for an id with a pending outbox entry doesn't overwrite the local row.
  - **Session expired:** a 401 on push keeps the outbox and sets `needs_signin`.
  - **Separate accounts:** `openUserDb("a")` and `openUserDb("b")` have independent outboxes.
  - **Saving a searched place twice** returns the same `kp_` id and creates one outbox entry.
  - **Local search** for `"bread"` finds a place whose diary note contains "bread".

### Task 3: Map adapter, markers and list picker

**Files:**
- Create in `apps/web/src/map/`:
  - `MapAdapter.ts`, `kakaoAdapter.ts`, `leafletAdapter.ts`, `loadMapAdapter.ts`, `kakaoColors.ts`;
  - `MapView.tsx`, `ListPicker.tsx`, `VisiblePlacesList.tsx`;
  - `loadMapAdapter.test.ts`, `ListPicker.test.tsx`.
- Create `apps/web/src/screens/MapScreen.tsx`.

**Interfaces:**

```ts
interface LatLng { lat: number; lng: number }
interface MapMarker { id: string; position: LatLng; color: string; label: string; kind: "saved" | "search" }
interface MapAdapter {
  readonly provider: "kakao" | "leaflet";
  mount(el: HTMLElement, view: { center: LatLng; zoom: number }): void;
  setMarkers(markers: MapMarker[]): void;          // clustered when zoomed out
  fitTo(points: LatLng[]): void;
  getCenter(): LatLng;
  onSelect(cb: (markerId: string) => void): void;
  showMyLocation(p: LatLng): void;
  destroy(): void;
}
function loadMapAdapter(config: PublicConfig, opts?: { timeoutMs?: number }): Promise<MapAdapter>;
```

- **Loading.** `loadMapAdapter` injects `https://dapi.kakao.com/v2/maps/sdk.js?appkey=<key>&autoload=false&libraries=clusterer` and calls `kakao.maps.load`. If there is no key, a script error, or a timeout (8 s by default), it resolves to the Leaflet adapter.
- **Marker colour:**
  - for a membership in a Kakao list, `KAKAO_PLACE_COLORS[kakaoColor]`;
  - for an own list, the list colour;
  - if neither, the theme primary.

  When a place is in several visible lists, the order is own lists first, then Kakao lists, then subscribed lists, each sorted by name.
- **List picker.** It has three sections: "My lists", "Kakao lists" and "Subscribed in Kakao".
  - Each list has a toggle, a colour and a count. Subscribed lists also show the owner's name.
  - There is "Show all" and "Hide all", per section and overall.
  - The selection is saved in `localStorage["mm.visibleLists.<userId>"]`, and **every list is visible by default**.
- **Map screen.**
  - The map fits to the visible places on first load.
  - "My location" asks for permission only when tapped.
  - Places without coordinates are counted under the map: "N places have no location yet — re-import from the extension".
  - A toggle switches between the map and `VisiblePlacesList`, an accessible list that is also the fallback when tiles fail.

### Task 6: Lists and import screens

**Files:**
- Create:
  - `apps/web/src/screens/ListsScreen.tsx`, `apps/web/src/screens/ListScreen.tsx`, `apps/web/src/screens/ImportScreen.tsx`;
  - `apps/web/src/import/runImport.ts`, `apps/web/src/import/runImport.test.ts`.

**Interfaces:**
- `runImport(onProgress: (p: { listIndex: number; listCount: number }) => void): Promise<ImportSummary>`. It runs these steps:
  1. `GET /api/import/kakao/source`, parsed on the client with the contract schema;
  2. `POST /api/import/runs` with `{ complete, importedAt }`;
  3. one `PUT .../lists/:kakaoFolderId` per list, in order;
  4. `POST .../complete` with every `kakaoFolderId`;
  5. then `syncNow()`.

  If it fails part-way, it throws `ImportError { step; listIndex? }`. Nothing is marked removed in that case, because the run never completed.
- **Import screen.**
  - One "Import from Kakao" button, a progress bar, and the summary afterwards (from i18n: "12 added · 3 removed from Kakao · 1 restored").
  - The last run's time and summary come from `/api/import/runs/latest`.
  - When the server returns `no_snapshot`, the screen explains how to import with the kakao-list extension first.
  - The button is disabled offline.
- **Lists screen.** Three sections like the picker.
  - "New list" takes a name and one of 8 preset colours.
  - Own lists can be renamed, recoloured or deleted. The delete confirmation says "places are kept".
- **List screen.** Places in order.
  - Kakao lists show memberships that were removed from Kakao at the end, marked as removed.
  - Tapping a place opens it.
